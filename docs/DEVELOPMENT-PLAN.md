# План развития: самостоятельные серверные NPC с оружием TaCZ

Подготовлен 10 октября 2026 после ревью текущего MVP 0.1.0. Документ можно передать ChatGPT/Codex как последовательную инструкцию. Он уточняет прежние `MILESTONES.md` и `CODEX_TASKS.md` под цель собственной сущности.

## Готовая вводная инструкция для ChatGPT

Работай в этом репозитории над сильными, честными, серверными NPC для Minecraft 1.20.1 / Forge 47.4.20 / Java 17 / TaCZ 1.1.8-hotfix2. Стратегическая цель — собственный NPC без обязательной зависимости от `[TACZ] NPCs`. Существующий NPCs 2.1.0 используй как переходный адаптер и эталон сравнения. Не меняй проверенную версию зависимости попутно с разработкой ИИ.

Сначала прочитай AGENTS.md, docs/INTEGRATION-AUDIT.md, docs/ARCHITECTURE-REVIEW-2026-10-10.md и релевантные `.agents/skills/*/SKILL.md`. В случае расхождения отличай реализованный код от проектных намерений. Разрешён переход к собственной сущности ради независимости; ненужное переписывание работающих подсистем не требуется.

Не делай новые модели, анимации, редактор или сложный интерфейс. Допускается минимальный vanilla renderer для проверки собственной сущности клиентом. Все решения и попадания авторитетны на сервере. Не повышай сложность через знание скрытых координат, отмену cooldown, лишний урон или мгновенный поворот.

Не копируй чужие ресурсы и большие фрагменты реализации ради независимости. При осознанном переиспользовании кода сохраняй применимые лицензии и attribution; вопросы распространения зависимостей рассматривай отдельно. Сначала используй проверенные API TaCZ и собственную реализацию необходимых систем.

Развивай поток `perception -> immutable snapshot -> decision -> action arbitration -> Forge/TaCZ adapter`. Ядро не импортирует Minecraft/Forge/TaCZ/NPCs. Forge-слой собирает данные и исполняет команды только на server thread. ИИ использует наблюдения и их историю; live-позиция скрытого игрока не доступна планировщику.

Выполняй этапы по порядку небольшими законченными срезами. После каждого показывай изменённые файлы, точные версии, фактические проверки и оставшиеся риски. Чистую Java проверяй `bash ai-core/run-tests.sh`; интеграцию — сборкой и подходящими Forge GameTests. Запуск `runServer`, ручные дуэли и профилирование заявляй только после реального выполнения. Не считай успешную сборку доказательством боевого поведения.

## Этап 0 — закрепить исходное поведение и устранить блокирующие проблемы

Задача для ChatGPT:

1. Исправь обслуживание оружия без видимой цели: пустой магазин, затвор, отсутствие боезапаса. Раздели намерение движения и оружейную операцию.
2. Определи допустимые режимы огня по данным TaCZ вместо безусловного SEMI. Неподдержанные свойства оружия блокируй с понятной диагностикой.
3. Уточни границы friendly-fire защиты: разброс, дробь, пробитие и союзник за целью. Добавь проверки на поддерживаемых образцах; неизвестные скриптовые свойства не объявляй поддержанными.
4. Разбей монолитный GameTest на понятные сценарии: no target, reaction, reload in cover, LoS loss, ally crossing, tag ownership, death/unload. Сохрани полноценный интеграционный smoke.

Критерий: NPC способен закончить/начать штатную перезарядку за стеной, не стреляет во время reload, корректно обрабатывает bolt и не дублирует исходный контроллер. Безопасность выстрела имеет явно описанный контракт и тесты.

## Этап 1 — сделать адаптеры настоящими архитектурными границами

Задача для ChatGPT:

- Введи `NpcRuntimeAdapter` и `GunController` в Forge-слое. Конкретный NPCs-адаптер скрывает AutoGunOperator, фракции и детали захвата исходных goals. TaCZ-контроллер работает через проверенный IGunOperator и Minecraft LivingEntity, сохраняя особенности конкретного runtime за контрактом.
- Убери прямые импорты NPCs из общих sensors/planner/commands. Не добавляй Minecraft-типы в ai-core.
- Замени набор boolean в snapshot на составные данные: `SelfState`, `Observation`, `WeaponState`, доступные позиции/маршруты и текущий `TacticalState`. Включи tick, dimension identity и generation; старые команды после unload/смены цели отклоняются.
- Решение содержит независимые движение, направление взгляда и оружейное действие. Арбитр выбирает одного владельца каждой подсистемы, проверяет актуальность и безопасность в момент исполнения.
- Убери безусловный `navigation.stop()` каждый тик. Введи удержание решений, TTL, смену команд по событиям и минимальный интервал перепрокладки пути.

Критерий: текущий NPC сохраняет рабочую стрельбу/перезарядку и восстановление goals, а тестовый адаптер позволяет проверить тактические решения без NPCs. Контракт отдельно выражает «двигаться к укрытию и перезаряжаться».

## Этап 2 — независимый NPC: минимальный проверенный срез

Задача для ChatGPT:

1. Сделай короткий эксперимент: собственный PathfinderMob, зарегистрированный EntityType/attributes, серверная команда создания, экипировка одним обычным TaCZ автоматом и минимальный renderer.
2. Проверь IGunOperator через TaCZ на реальной сущности. Подтверди initialData/cache/draw, cooldown, magazine/chamber, reload, bolt, ammo policy и синхронизацию. Не дублируй native tick обслуживания из AutoGunOperator.
3. Подключи существующее ядро через новый runtime adapter. Никакого наследования от AutoGunOperator и вызовов его static create в независимом пути.
4. Добавь версионированный NBT: loadout, faction, настройки поведения, ammo policy, служебный идентификатор. Живые ссылки на цели и готовые navigation paths не сохраняй.
5. Выдели NPCs compatibility в отдельный build artifact или строго изолированный optional module. Снятие mandatory в mods.toml само по себе недостаточно: в самостоятельном варианте не должны грузиться классы NPCs.
6. Проверь запуск сервера и клиента с TaCZ + собственным модом, **без tacznpcs JAR**. Повтори spawn, equip, save/restart, chunk unload/load, смерть и смену измерения.

Критерий: собственный NPC проходит базовый бой и lifecycle без установленного NPCs. Новых моделей/анимаций нет. Если spike выявляет недостающую часть TaCZ lifecycle, сначала документируй и закрой её, затем расширяй тактику.

## Этап 3 — восприятие и память о противнике

Задача для ChatGPT:

- Добавь ObservationMemory: последняя известная позиция, время, источник, confidence, радиус неопределённости и срок действия.
- Источники: подтверждённое зрение; проверенное серверное событие выстрела/урона; позднее — squad report. Сам факт нанесённого урона не должен автоматически раскрывать точные координаты стрелка за стеной.
- Раздели FOV, задержку восприятия, задержку реакции, turn rate и точность. Позицию/скорость оценивай только из зарегистрированных наблюдений.
- При потере LoS заморозь последнюю известную позицию, расширяй неопределённость, затем переходи SEARCH -> PATROL/HOLD. Не обновляй её через getPlayerByUUID/getEntity.position при скрытой цели.
- Расстояние обнаружения, дальность памяти и рабочую дистанцию оружия сделай отдельными параметрами.

Критерий: игрок скрывается и меняет позицию — NPC помнит старую область, не ведёт прицел по новой скрытой позиции и забывает устаревшие сведения. Слух работает с приблизительной областью, а не с точным невидимым hitbox.

## Этап 4 — прятаться, выглядывать, менять позицию

Задача для ChatGPT:

1. Реализуй локальный CoverSensor: ограниченное число кандидатов, геометрия eye/torso, защищённость относительно **известного** направления угрозы, доступность подхода и точки выглядывания. Не используй скрытого игрока как источник точной геометрии угрозы.
2. Состояния: TAKE_COVER -> HOLD -> PEEK -> REPOSITION; добавить ADVANCE и RETREAT. Основные стимулы: урон, пустой магазин, неудачный угол стрельбы, длительная экспозиция и устаревание позиции.
3. Раздели MovementPlanner и навигационный executor. Проверяй достижимость, cooldown path requests, stuck detection, blacklist/backoff неудачных мест и минимальное удержание позиции.
4. Учитывай стены, ступени, полублоки, двери, ямы, воду/лаву и границы загруженных чанков. Не загружай чанки и не ломай блоки ради укрытия по умолчанию.
5. Введи общий бюджет на уровень для rays/candidate checks/path requests, затем лимиты на NPC. Разнеси тяжёлые обновления по тикам.

Критерий: на тестовой карте NPC реально закрывает тело препятствием, безопасно выглядывает, перезаряжается в укрытии и выбирает другое место при недостижимости. Нет отмены пути каждым тиком, дрожания между двумя укрытиями и бесконечных retries.

## Этап 5 — стрелять в примерное местоположение игрока

Задача для ChatGPT:

- Введи отдельные режимы `DIRECT` и `SUPPRESS_AREA`; не ослабляй глобально правило visible в ActionArbiter.
- DIRECT использует актуальное зрительное наблюдение. SUPPRESS_AREA требует легитимной свежей памяти/слуха/доклада, допустимого возраста и confidence, ограниченного расхода патронов и пауз.
- Для SUPPRESS_AREA выбирай точку в известной области, например последний видимый край укрытия/проём. Не получай текущую позицию скрытого Player для вычисления направления.
- На первом срезе не реализуй намеренную стрельбу сквозь стены: если линия до выбранной точки перекрыта, откажись от выстрела или выбери наблюдённый край. Это позволяет держать простое правило безопасности. Wallbang возможен только как отдельный будущий аудит оружия/материала/геометрии.
- Проверяй allies, безопасный сектор и свойства боеприпаса перед каждым разрешённым оружейным действием. Не обходи TaCZ cooldown/reload/spread. Не запускай бесконечный огонь по исчезнувшему игроку.
- Обнови соответствующий skill/test contract: прежнее требование «только видимая цель» остаётся для DIRECT, для SUPPRESS_AREA нужны отдельные явно заданные основания. Согласуй docs/TEST_PLAN.md и GameTests с двумя режимами.

Критерий: NPC ограниченно обстреливает последнюю известную область/проём; игрок за стеной меняет положение, а направление не следует за ним. Память истекла — огонь прекращён. Преграда и союзники всё ещё блокируют небезопасную команду.

## Этап 6 — оборона, атака и различное оружие

Задача для ChatGPT:

- Введи приказ/характер поведения: DEFEND_AREA, HOLD_POSITION, ASSAULT, PATROL; текущий боевой state определяй отдельно.
- Оборона: якорная позиция, leash/radius, укрытия, ограниченное преследование и возврат. Атака: продвижение через доступные укрытия, смена угла и отход при угрозе/перезарядке.
- Введи профили SMG/AR/DMR/sniper/shotgun/LMG по подтверждённым метаданным TaCZ: желательная дистанция, допустимые режимы, очередь/пауза, время экспозиции и движение при выстреле. Класс поведения можно задавать серверным конфигом, но техническую совместимость проверяй по данным оружия.
- Для неизвестного gunpack используй консервативный профиль или блокировку с диагностикой. RPG, charge, inventory-fed и explosive поддерживай отдельными срезами после обычного оружия.
- Упреждение добавляй только после проверки единиц скорости/баллистики и на свежих видимых наблюдениях. Не делай идеальную компенсацию движения и headshot.
- Конечный и бесконечный резерв сделай явными серверными настройками с корректным поведением при исчерпании.

Критерий: SMG сокращает дистанцию, снайпер предпочитает дальнюю позицию, shotgun не ведёт одинаковый с автоматом бой с 40 блоков. Защитник удерживает область, атакующий действительно продвигается. Native механика каждой проверенной модели сохранена.

## Этап 7 — несколько NPC и серверный выпуск

Задача для ChatGPT:

1. Сначала проверь независимых NPC в 1v4. Затем добавь SquadBlackboard на уровень, задержанные отчёты, роли прикрытия/обхода и cover reservations с TTL. Squad report передаёт наблюдение и возраст, а не доступ к скрытому Player.
2. Проверь одинаковые позиции, взаимное перекрытие секторов, смерть лидера, потерю цели, разрыв squad и освобождение claims при unload/death.
3. Добавь счётчики rays/paths/cover/active NPC и sampled telemetry. Отладка боя не должна выполнять синхронный I/O каждый тик.
4. Замерь 1/4/16/30/50 NPC на обычном выделенном сервере: baseline, бой, динамические препятствия, низкий TPS, unload/load и длительный прогон. Фиксируй CPU/RAM, мир, модлист, p50/p95 tick, AI time, пути/лучи, память и ошибки.
5. По результатам настрой activation radius, LOD и общие бюджеты. Дальние NPC не получают права знать игроков вне сенсоров. Асинхронность добавляй только при измеренной необходимости; workers получают immutable данные, результаты проверяются по generation/target validity.

Критерий релиза: dedicated startup, подключение клиента, бой с человеком 1v1/1v4, оружейная матрица, save/restart/lifecycle и ≥30 NPC профиль реально выполнены. Цели 20 TPS и ≤2 ms AI p95 — начальные ориентиры на указанном оборудовании, не уже доказанные характеристики.

## Минимальный функциональный результат

Собственный NPC создаётся и сохраняется без NPCs; пользуется проверенными TaCZ автоматом/пистолетом/дробовиком/винтовкой; видит и запоминает честно; прячется, выглядывает и меняет позиции; ограниченно подавляет последнюю известную область; умеет оборонять точку и наступать; устойчив при смерти, перезагрузке мира и массовом бою. Новая графика остаётся отдельным последующим этапом.
