# План перехода Tactical NPC AI от MVP к alpha

Основание: [ревью 11.10.2026](ALPHA-CODE-REVIEW-2026-10-11.md). Стек остаётся Minecraft 1.20.1 / Forge 47.4.20 / Java 17 / TaCZ 1.1.8-hotfix2, optional NPCs 2.1.0. Ниже целевое поведение и начальные гипотезы баланса, не уже реализованные возможности.

## Цель alpha

NPC быстро отвечает на контакт, опасен в перестрелке и умеет продолжать бой после исчезновения игрока. Он выполняет приказ и возвращается к нему после боя. При отказе маршрута не зависает на месте. Alpha считается готовой по сценариям и человеческим испытаниям, а не по числу состояний или библиотек.

Сохраняем один core и адаптеры. Первое улучшение должно быть играбельным без SmartBrainLib и без новых моделей. Затем проверяем SBL изолированно и выбираем одну реализацию scheduler для alpha.

## 1. Устранить пассивность и ускорить цикл боя

В первую вертикальную задачу включить R1–R6 из ревью: emergency priority, route recovery, reacquire, cooldown, выход из HOLD, свежий tracking. Это даст больше эффекта, чем добавление ещё нескольких nominal intents.

Разделить временные шкалы:

- **Каждый server tick:** обновление активного визуального контакта, aim tracking, актуальная готовность оружия, execution safety.
- **Раз в 2–4 ticks / по событию:** поиск новой цели в активной зоне; потеря контакта, damage, target switch, завершение пути/перезарядки прерывают ожидание, когда это влияет на решение.
- **Реже и с бюджетом:** tactical scoring, cover/flank candidates, route rebuilding. Политика не обязана менять манёвр каждый tick.

Стартовый профиль Hard для подбора:

| Параметр | MVP | Начальный alpha-кандидат |
|---|---|---|
| Активный acquisition | 10 ticks, затем 2 при candidate | 2–4 ticks со staggering и общим бюджетом |
| Perception | 4 ticks | 1–2 ticks |
| Первый reaction | 6 ticks, минимум в config 4 | 2–3 ticks; при необходимости расширить config bounds |
| Повторное появление того же свежего контакта | Полный новый цикл | 1–2 ticks; без разрешения огня сквозь стену |
| Поворот | 10°/tick | Начать с 16–18°/tick; более высокие значения только после измерения |
| Обновление точки aim | Обычно раз в 4 ticks | Каждый tick при свежем VISION |
| Path retry после отказа | Фиксированные 160 ticks | Быстрый ограниченный retry альтернативы, затем возрастающий backoff |

Замерять first visible sample → first native projectile, отдельно scan/perception/reaction/turn/draw/ADS/native cooldown. Часть задержек должна идти параллельно. Целевой ready/aligned first-contact ответ: ориентировочно **150–350 ms при 20 TPS** после настройки pipeline; reacquire заметно быстрее. Это бюджет для конкретного стенда, не обещание для NPC, повернутого спиной или занятого reload. У native TaCZ cooldown/reload/draw нет исключений.

Человечность сохраняется finite turn, aim error, решениями и временными ошибками, а не обязательной большой паузой перед каждым выстрелом. Не повышать одновременно damage, HP и точность: иначе нельзя понять эффект улучшения.

Приёмка: короткие повторные peek перестают быть гарантированно бесплатными; при health emergency NPC немедленно выбирает безопасное действие; неподходящий cover не создаёт бесконечный HOLD; blocked route приводит к альтернативе или явному отказу; завершение cooldown не ждёт лишнего policy cycle.

## 2. Ввести нормальный бег и раздельные скорости

Убрать безусловный `setSprinting(false)` и добавить явную locomotion policy: patrol walk, pursuit/relocation run, combat strafe, peek, retreat. Команда должна содержать режим скорости; `MovementExecutor` применяет его, `GunController` сохраняет native TaCZ sprint/ADS/fire ограничения.

Начать с умеренного множителя pursuit navigation (например 1.2–1.3 как гипотеза), затем калибровать. Не подставлять player attribute напрямую в mob attribute и не выдавать коэффициент navigation за blocks/second.

На одной прямой плоской полосе измерить реального игрока с обычным sprint, NPC без оружия/с оружием, NPC в ADS. Убрать разгон из участка замера. Цель pursuit: фактическая скорость рядом с обычным player sprint; strafe и peek медленнее. При сближении заранее прекратить sprint и дождаться native возможности стрелять. На углах, лестницах и у края NPC должен снижать скорость, а не проваливаться.

Приёмка: игрок не отрывается от исправно преследующего NPC только из-за систематически медленного бега; sprint не ускоряет native RPM и не создаёт стрельбу в запрещённом TaCZ состоянии.

## 3. Реализовать задачу, контакт и боевую подзадачу отдельно

Разделить постоянный **Mission/Order** и временный **CombatTask**. Минимум: Patrol / HoldPosition / DefendArea / Assault; контакт: Acquire / Engage / Pursue / Search / Return. Weapon action и movement остаются независимыми каналами с arbitration.

### Patrol

Route содержит несколько проверенных точек, index, anchor, patrol bounds и ограниченные паузы осмотра. Точка меняется по достижению или признанному отказу, а не по одному глобальному таймеру. Seed даёт воспроизводимую вариативность маршрута и остановок.

После обнаружения NPC сохраняет route/index и запускает Engage/Pursue как подзадачу. Combat leash и chase timeout отдельно от patrol radius: разрешить выход из patrol area в контролируемых пределах. При убийстве цели, её невалидности или завершении поиска — Return к доступной точке маршрута, затем продолжение patrol. Не объявлять любую потерю LOS ликвидацией. Если цель неожиданно появляется при Return, снова вступить в бой.

### Hold / Defend

Hold сохраняет точку и разрешает только малые локальные перестроения/выходы; не превращается в погоню. DefendArea разрешает манёвр внутри защищаемой зоны. Если нельзя выполнить приказ, показывать причину в диагностике. В alpha добавить приказ на выбранную позицию, а не только anchor в текущем положении NPC; поддержать selectors для группы.

### Assault

Assault — агрессивное движение к цели штурма/контакту с поиском подхода и firing positions. В упоре NPC не обязан буквально идти в hitbox игрока: сохраняется оружейная дистанция, возможность flank/retreat/reload. Для каждого окна возможности выбирать push, удержание угла, короткую очередь, смену позиции; оценивать дистанцию, ammo, здоровье, укрытие, недавний урон и наличие союзника.

Приёмка: Patrol → fight → pursuit → elimination → return → Patrol проходит целиком; Hold не уходит за игроком; Assault продолжает давление после двух углов и умеет признать недостижимый маршрут.

## 4. Добавить запрошенное преимущество информации: AssaultAssist

Пользователь явно просит NPC с вероятностью знать скрытое положение обнаруженного игрока. Это сознательное исключение к текущим fairness-инструкциям AGENTS.md, skill guidance и описанию Observation; при реализации документировать узкое исключение. Запрет использовать неизвестные координаты для DIRECT aim/fire остаётся.

Рекомендую две policies: **ObservedOnly** и **AssaultAssist**. Hard Assault preset включает второй; глобального всеведения на всех NPC нет. Отдельное включение assist для боевой подзадачи Patrol позволяет получить требуемую агрессивную погоню, не потеряв маршрут.

Начальные параметры для A/B:

- Триггер только после подтверждённого VISION-контакта с конкретным UUID.
- Вероятность 0.8 один раз на новый контакт/эпизод, а не каждый tick. Не перекидывать решение при каждом peek: иначе вероятность быстро станет практически 100%.
- Максимальный эпизод 8–12 секунд после последнего настоящего visual contact; обновления hint раз в 8–12 ticks, ограниченный chase range и только загруженные области текущего level.
- В момент update сервер может взять точную скрытую позицию **этого ранее обнаруженного игрока**. Между updates это snapshot, не живой entity reference и не точный текущий tracking.
- Отдельный immutable `PursuitHint(subject, position, sampledAt, expires, source=ASSISTED)`; его нельзя записывать в VISION Observation. Навигация использует hint; aiming/знание для suppression — только обычные Observation/known geometry.
- Hint не продлевает сам себя бесконечно; очистка при TTL, смерти, logout, dimension change, смене faction/order/target и unload. Новый реальный visual contact может начать следующий эпизод по определённой политике.
- Радио assist hints по умолчанию не распространяет. Если позже разрешить — источник и ограничения должны оставаться явными.

Цена такого подхода: спрятавшийся игрок иногда всё равно будет найден. Польза: NPC сохраняет инициативу при недостаточном поиске. Навигационная помощь не должна скрывать застревания и плохие решения. Отдельно сравнить ObservedOnly и AssaultAssist на тех же seeds/картах. После улучшения search можно ослабить assist.

Приёмка: за стеной игрок перемещается — pursuit destination меняется в разрешённом режиме; DIRECT aim не следует за скрытым hitbox и не стреляет через стену; ещё не замеченный игрок никогда не получает hint; TTL и очистка работают. Игра с assist отличается от ObservedOnly воспроизводимо.

## 5. Сделать suppression осмысленным

Сохранить уже работающие отдельный SUPPRESS permit, native rounds и checks. Добавить `SuppressionRegion`: известный проём/последняя видимая зона/доступные точки вероятного выхода, время наблюдения, uncertainty, источник и quota. Геометрию doors/windows определять по реально увиденной области/ограниченному анализу вокруг last-seen; не обследовать все здания мира.

Важно отделять **блокировку актуального луча** от **незнания, где скрытый игрок**. NPC может стрелять в открытый дверной проём, где недавно был противник, не зная его текущего положения. Сплошная стена всё ещё блокирует выстрел; прострелы — отдельная будущая механика, не побочный эффект assist.

Выбирать несколько доступных точек внутри известной области с seed и небольшим разбросом; проверять каждый фактический ray и союзников. Не зажимать все переходы одним повторяемым таймером. Начальные короткие очереди 2–4 rounds, паузы, общий лимит; не увеличивать нынешнюю квоту 6 native rounds до отдельного балансного замера. Вероятность suppress зависит от роли, боезапаса и участия союзника, а не только от существования памяти.

Сейчас permit привязан к одной `Observation.position()`. Для региона требуется изменить контракт permit/aim и native gate вместе: простая замена aim point будет отклоняться существующей equality-проверкой. PERMIT authorizes регион и provenance, executor authorizes конкретный sampled ray. Assist position не становится suppression provenance.

Приёмка: игрок скрылся за углом — NPC иногда обстреливает прежний проём/известный выход; меняет точки внутри допустимой области; прекращает после TTL/quota; союзник, пересёкший огонь, защищён; ложный hidden hint не даёт разрешения SUPPRESS.

## 6. Дать манёврам и отряду реальный смысл

Минимальный alpha набор: hold firing angle, lateral reposition, ограниченный flank route, push при reload/длительной пассивности цели, отступление к доступной позиции при собственном reload/критическом HP. События должны быть действительно наблюдаемыми; reload противника нельзя объявлять известным без подходящего сигнала.

Utility scoring + commitment вместо растущего каскада overlays: варианты оцениваются, победивший удерживается до срока/события, emergency прерывает. Выбор среди нескольких близких оценок с seed даёт вариативность, не случайный шум каждую секунду. Использовать `commitUntil` содержательно.

Для 1v4: ANCHOR удерживает сектор, SUPPRESSOR подавляет известный выход, FLANKER движется по проверенному альтернативному маршруту; не более одного flank в маленькой группе. Нужны route candidates в snapshot — сейчас runtime их не передаёт. Cover claims, delay/radius и lifecycle сохранить. Не всем NPC одновременно выходить на одну firing point.

Приёмка: как минимум два разных осмысленных подхода на одной карте, детерминированных при одинаковом seed; роли видны по действиям; группы не толпятся в одной двери; не возникает второго владельца navigation/fire.

## 7. Проверить SBL и готовые NPC, принять решение по доказательствам

Короткий SBL 1.15 spike после первого рабочего улучшения: собственная entity, custom sensors, минимум Patrol/Engage/Return, тот же core и исполнители. Проверить exact JAR/hash/API в INTEGRATION-AUDIT; не переносить примеры новой SBL ветки вслепую. Сравнить latency, объём связанного scheduler-кода и бюджет. Удалить/отключить старый goal scheduler в этом runtime до включения нового.

Параллельно по порядку разработки, без обязательного параллелизма агентов: ручной A/B с обычным NPCs 2.1.0 и Simple Enemy либо CustomNPCs-интеграцией на изолированных мирах. Выбрать максимум одного внешнего кандидата для глубокой оценки, чтобы не потратить alpha на универсальную интеграционную платформу.

Если остаёмся на NPCs shell, расширить runtime capabilities: чтение/установка order, squad, faction/ammo policy там, где поддержано, persistence отдельного tactical state. Команды работают через adapter capabilities и сообщают unsupported явно. Не менять сторонние template/resources и не копировать maintenance tick.

## 8. Alpha gate

Вести один regression manifest и точные команды/логи. Новый probe из ревью подтверждает старое поведение; после исправления соответствующих ошибок его ожидания нужно заменить настоящими regression assertions.

| Слой | Обязательная проверка |
|---|---|
| Core | `bash ai-core/run-tests.sh`; emergency precedence, reacquire timing, recovery, mission resume, assist provenance/TTL, suppression region, seeded decisions |
| Forge | Standalone и optional NPCs GameTests, native ammo/reload/bolt/BURST, target switch, blockers, allies, lifecycle/NBT |
| Movement | Flat sprint, двери/лестницы/полублоки, два угла, другой этаж, недостижимая точка, границы chunk |
| Бой | Scripted moving/peeking targets и реальные 1v1/1v4 на 2–3 картах с одинаковым оружием/HP |
| Telemetry | Reaction distribution p50/p95, time without useful action, stuck/retries, shots/hits/TTK по дистанции, chase recovery, причины запрета огня |
| Dedicated | Ordinary runServer на pinned versions; standalone и compat; без test pacing |
| Performance | 1/4/16/30/50, idle/cover/chase/suppression, p50/p95 AI и общего tick, TPS, rays/paths, несколько повторов |
| Стабильность | Unload/reload, disconnect/reconnect, смерть/смена измерения, сохранение приказа, минимум длительный часовой soak |

Автоматические 1v4 с FakePlayer доказывают технические свойства, не конкурентность против человека. Для первого баланса собрать хотя бы 20 повторов каждого главного сценария; win rate интерпретировать с учётом уровня игрока, позиции и экипировки. Не объявлять универсальный «правильный процент побед» без такого контекста.

Performance ориентиры проекта сохраняются как цели, а не пройденные требования: общий tick p95 ниже 50 ms на объявленном оборудовании, AI p95 стремится к ≤2 ms для 30 NPC. Предыдущий профиль этот AI ориентир не выполнил. Если новая реакция выходит за бюджет — сначала уменьшать второстепенный cover sampling, а не сбрасывать активные контакты. Результаты synthetic arena не переносить автоматически на здания и chase/pathfinding.

## Очерёдность поставки

1. **Alpha-1:** responsiveness + исправление P1/P2 пассивности + измеряемый бег.
2. **Alpha-2:** полный mission/combat/return цикл; runtime commands; ObservedOnly и отдельный AssaultAssist.
3. **Alpha-3:** suppression regions, reachable flank, различимые squad roles.
4. **Alpha-4:** решение по SBL/оболочке, dedicated/regression/performance/human balance gate.

Каждый этап заканчивается играемой сборкой и короткими release notes с фактическими тестами. Новые renderer, vehicles, grenade systems и универсальные сторонние adapters не нужны для доказательства боеспособности первой alpha.
