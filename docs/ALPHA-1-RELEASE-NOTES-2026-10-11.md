## Что реализовано

Точные repo-relative пути и SHA-256 до/после перечислены в [change manifest](testing/alpha1-change-manifest-2026-10-12.json); исходные файлы доступны в указанной ниже резервной копии.

- `ai-core/.../CombatBrain.java`, `MovementPlanner.java`: critical HP имеет приоритет над старым PEEK/HOLD/cover cycle; RETREAT не перезаписывается. Старый peek path останавливается сразу даже при DEFERRED нового path request. BOLT и пустой магазин прерывают прежний peek; для HOLD без usable peek установлен порог 48 ticks, проверяемый при tactical replan (интервал максимум 4 ticks); выбранное укрытие отвергается и позиция переоценивается.
- `ai-core/.../CombatDecision.java`, `MovementCommand.java`, `RouteRecovery.java`, `forge-addon/.../MovementExecutor.java`: REPOSITION без cover задаёт реальную локальную точку. Единственный executor проверяет standing surface, loaded chunks, order bounds, Path.canReach и hazards. После отказа — максимум три локальные альтернативы, не чаще одного path request / owner / 4 ticks и восьми / level / tick; episode timeout 60 ticks, пауза после исчерпания 20. Backoff 20/40/80 ticks относится к конкретной точке; кеш максимум 16. Stuck detection 20 ticks. Reacquire может отменить старую попытку navigation, сохраняя blacklist. EXHAUSTED/FAILED/ALTERNATIVE/ARRIVED отражены в counters. Это локальный recovery, не полноценный reachable flank.
- `ContactReadiness.java`, `TacticalCombatGoal.java`: contact UUID отдельно от visible. Тот же настоящий visual contact в течение 60 ticks использует короткий reacquire. Loss of sight сразу закрывает DIRECT и инвалидирует старый Frame; неизвестные координаты в memory не попадают. DEFERRED сохраняет identity/readiness, но не разрешает огонь. Death/TTL/unload/target change сохраняют invalidation. Public targetId() по-прежнему обозначает видимую цель, contactId() — сохранённую идентичность.
- CombatBrain больше не запекает native cooldown/volley readiness в fire intent. Arbiter и TaCZ каждый tick проверяют актуальную готовность; native round gate сохраняет geometry/allies/busy/TTL/generation и дополнительно закрывает rounds при emergency/sprint. Native shoot/reload/bolt/cooldown не сбрасываются, пули вручную не создаются.
- DIRECT tracking обновляет точку каждый tick только из свежего VISION того же UUID, без смены tactical Frame. Hidden samples и другой UUID отвергаются. AimLead в production не подключён.
- `VisibilitySensor.java`, `AiWorkBudget.java`, `CoverSensor.java`: CLEAR/BLOCKED/DEFERRED; optional rays ограничены 128 / level и 12 / owner внутри прежних total 384 / 16, оставляя резерв active LOS/native rounds. Active check выполняется до cover. Поиск peek продолжает cursor между бюджетными обновлениями, а не бесконечно проверяет только ближайшие закрытые выходы.
- Явная locomotion: patrol WALK=1.0, pursuit RUN=1.25, relocation=1.25, PEEK=.65, RETREAT=1.1 для navigation; combat strafe остаётся отдельным каналом. Sprint включается только на выполняемом пути, сбрасывается на отказе/arrival/смене режима; native getProcessedSprintStatus и sprintTime сохраняют ADS/reload/fire ограничения. Коэффициенты не являются blocks/s и не скопированы из player attribute.
- `ServerConfig.java`: начальный Hard 1 perception / 3 reaction / 1 reacquire / 3 active acquisition со staggering / 17 degrees per tick. Диапазон подбора 1–2 / 2–3 / 1–2 / 2–4 / 16–18. Старые world overrides сохраняют силу. `/tacticalnpc hard` применяет начальные значения к текущей конфигурации; долговременные значения проверять в server config. Target latency не объявляется достигнутой универсально.
- `AiTelemetry.java`, `ShotSafetyEvents.java`, `DebugCommands.java`: bounded per-level histogram first-contact/reacquire до настоящего EntityKineticBullet join; fire-gate и route counters. `/tacticalnpc diagnostics` показывает агрегат, `telemetry=true` выводит его раз в 200 ticks. Нет нового I/O каждого NPC tick. Latency начинается с первого визуального sample, отдельно от ожидания scan. Bucket 128 — overflow >=128, mean при overflow является нижней оценкой. Распределения агрегированы, не per-target logs.

## Замеры и ручная приёмка

Корректный NPC lane sample: 60 ticks после разгона, одинаковая сухая закрытая прямая полоса длиной 50 блоков до goal, свежий actor на каждый проход, native FOLLOW_RANGE соблюдён, primary path без recovery. [Combined acceptance log](testing/alpha1-combined-acceptance-2026-10-12.log) содержит координаты, ground state, recovery status и оба способа расчёта скорости:

| Режим | blocks/s при пересчёте на 20 TPS | blocks/s по реальному времени |
|---|---:|---:|
| WALK | 2.6982 | 2.2060 |
| RUN без оружия | 7.1250 | 5.8469 |
| RUN с native AK-47 | 6.3965 | 5.1966 |
| WALK с native AK-47 ADS | 1.5503 | 1.2728 |

Во всех measurement ticks NPC оставался на исходной высоте и прямой, вне воды; пути не переходили в recovery. ADS progress >.9 и отсутствие forced sprint проверены. Это NPC measurement под нагрузкой тестового сервера; навигационные run coefficients — начальная настройка, не гарантия паритета с player sprint. Разницу normalized и wall-clock результатов нельзя выдавать за 20 TPS perf pass.

Latency fixture использует точные значения perception=2/reaction=3/reacquire=1/acquisition=4/turn=17, ready/aligned неподвижный HOLD и прогретое native оружие. Это точка внутри диапазона Hard; command/default Hard равен 1/3/1/3/17. Финальные wall-open -> projectile samples: standalone **6 ticks first / 2 reacquire**, combined **9 / 2**. Задержка scan входит в wall-open fixture, но встроенный firstProjectile histogram начинает отсчёт с первого visual sample. Reacquire быстрее первого контакта в проверенной последовательности; универсальный target latency не заявлен.

Ручное сравнение ещё не выполнено: настоящий player без speed effects на той же полосе (обычный sprint), NPC без оружия / AK-47 / ADS, одинаковый пол/направление/участок без разгона. Не заменять игрока FakePlayer и не брать player attribute как коэффициент mob speed. После сравнения настраивать RUN/relocation и повторить corners/stairs/edges и sprint -> ADS -> native fire. Нынешний speed GameTest измеряет только NPC.

Не выполнены в этом срезе human 1v1/1v4 balance, новый >=30 NPC JFR/perf/длительный soak, distribution-JAR запуск через отдельный launcher и полная матрица maps/gunpacks. Старые PROFILE-REPORT/JFR остаются историческими и не подтверждают новый Hard sensor cadence. Native BURST/ally/wall/cooldown checks в текущей test suite обязательны, но FakePlayer 1v4 — функциональный smoke, не человеческий баланс.

Не реализованы последующие срезы: mission/chase/return route/index, отдельные Hold/Assault capabilities для групп и optional shell, AssaultAssist/PursuitHint, suppression regions, reachable flank/новые роли, SBL. Узкое fairness исключение для будущего assist здесь не применяется: скрытые координаты не добавлены.
